# NexaAsset Editor v2 — reliability audit

Date: 10 October 2026. Branch: `feat/nexaasset-editor-v2-dark-ui`.

## Scope and assurance

This audit verifies the supplied review findings against the current implementation and examines the asset-processing and UI lifecycle paths most directly related to data integrity, stale callbacks and retained native resources. The source inventory includes 300 ActionScript/MXML files after adding the remapping helper. A repository-wide search covered stream creation, bitmap allocation/disposal, timers, subscriptions and callback registration. Detailed inspection focused on the classes identified below; this is not a claim that every source line or every bundled library has been independently audited.

The application is managed ActionScript 3, not C++ or Rust. The reviewed source has no native C++ smart-pointer ownership to convert. Garbage collection handles managed object references, but file streams, bitmaps and scheduled callbacks still require explicit lifecycle control. A short test run cannot establish an absolute absence of leaks, disposed-resource access, corruption or defects in the AIR runtime and bundled SWCs.

The original editing foundation, source notices and file-format contracts are retained. No speculative deletion of apparent dead code, parser redesign or unrelated dependency upgrade was performed.

## Additional verified corrections

| Area | Confirmed problem | Implemented change |
| --- | --- | --- |
| Confirmation presentation | `nail.components.controls.Alert` retained its legacy gray skin. Portuguese and Spanish lacked the paste confirmation message. | Reuse the dark TitleWindow skin through the shared Spark host contract; add the missing translations. Preserve Yes, No, drag, Close and callback behavior. |
| Recycled thumbnails | A bitmap exception could leave the previous object's image visible. | Clear the image on failure rather than displaying an unrelated thumbnail. |
| Reader lifecycle | Reopening one SpriteReader across standard/multi formats could retain the previous stream or multi-reader state. | Close/reset before every open, close both resource kinds and clean up failed multi opens. |
| Output completion | A Windows sharing violation can leave a staging file unmoved without throwing. DAT also emitted success events after a failed compile. | Check move postconditions; report failure rather than success and emit DAT completion events only on success. |
| Sprite dirty state | Successful mutations depended on the presence of a CHANGE listener to mark storage dirty. | Record dirty state independently of optional listeners. |
| Selection debounce | A queued object request could survive document clearing/replacement. | Cancel/reset the timer at lifecycle boundaries and verify the loaded document before sending a request. Clear the sprite grid alongside the sprite list. |
| File-path debounce | A delayed path callback could fire after a programmatic selection or dialog removal. | Reset the timer on programmatic file assignment and removal from the stage. |
| Storage queue | Empty queues failed, errors left the queue running and stale LOAD events could advance it. | Subscribe only to the active storage, handle thrown/dispatched errors, stop on failure and remove terminal listeners. Completed queues remain reusable. |
| Destructive imports | Preview-oriented reads can substitute an error bitmap for a corrupt record. Merge/bulk paths also ignored failed sprite insertion or missing mappings. | Add strict import reads, check insertion results and reject missing remaps before installing the affected object. Keep preview fallback confined to preview-oriented reads. |
| Merge error lifecycle | Temporary source storages and terminal callbacks were not cleaned up consistently on failure. | Unload temporary storages, remove listeners, propagate an error and dismiss worker progress on failure. |
| Bulk replacement | Header errors could leave streams open; signatures were read with inconsistent byte order; the multi index was treated as a sprite signature. | Close headers in `finally`, read DAT little-endian and use SpriteReader for standard/multi signatures. Unload sources on all reached error paths and stop on strict-import failure. |
| Sprite optimization | Invalid referenced IDs could be encountered after remapping started; corrupt sprites could enter via preview fallback. | Preflight references before mutation and use strict sprite reads before deduplication. |
| Worker render cache | The largest document thumbnail buffer remained allocated after unloading assets. | Dispose/reset the worker buffer at unload. Remove the bulk-replace forced-GC hint now that source cleanup is explicit. |

`ThingSpriteMap` is a small shared helper for clone-and-remap validation, not a new serialization format. Test-only package access compares compressed SPR payloads without widening their production visibility.

## Validation

The runners check external command exit codes and stop on failure:

```powershell
./build.ps1 -BundleName 'NexaAsset-Editor-v2-review-20261010'
./tests/run.ps1 -RealAssets '<retained 8.60 test-copy directory>'
./tests/run-ui.ps1 -RealAssets '<retained 8.60 test-copy directory>'
git diff --check
```

The local asset dataset contains 485,804 sprites, item IDs through 54,751 and 1,977 outfits. Tests write to ignored output directories, not the source dataset.

Asset coverage includes:

- Legacy 65,535 and extended 65,536 sprite boundaries; 65,536 DAT items; rejection of count truncation.
- Standard-to-multi, multi-to-standard and in-place multi recompilation; non-sequential and invalid locators.
- RGB/RGBA conversion, sparse/ambiguous feature detection and red/yellow option warnings.
- Locked SPR/DAT destinations, no false success events, multi-file rollback and retained backups.
- Twenty-five close cycles and standard/multi/standard reader reuse, including a Windows rename proving release of the old handle.
- Strict corrupt-RLE rejection, failed full-capacity merge, missing remaps, optimizer reference preflight and dirty state without listeners.
- Empty, failed, thrown, stale and reused storage queues.
- Recompile/reopen of the real DAT/SPR project. Every logical SPR record is validated and its compressed payload compared; sampled decoded pixels and DAT counts are also checked.

UI coverage includes the actual application controls at 1366×768, 1600×900 and 1920×1080 logical sizes, English/Portuguese/Spanish labels, three editor tabs, repeated navigation, both list-renderer bounds, Save/clipboard regressions and actual confirmation callbacks. The popup image was visually inspected: its message, title and Yes/No buttons are readable on the dark surface. No/Close tests verify that closing does not confirm replacement. File-input timers are checked after their original one-second deadline, and selection cancellation after the original 150ms deadline.

The 1.25×/1.5× captures render enlarged display lists; they are not a change to physical Windows DPI settings.

One completed real-data run compiled the standard SPR in 7.08 seconds and completed the asset checks, including the full payload comparison, in 55.5 seconds. These are local observations, not an isolated benchmark or a demonstrated speedup relative to Object Builder 5.5 or the separate Rust editor. Cache state, concurrent builds and disk performance affect timings.

## Remaining limitations and risks

- The application-subclass harness still logs `RegisteredCallbacksCommand`, `BackgroundWorkerStartedCommand` and a `ThingData.category` binding diagnostic. Its load/UI assertions pass, but the diagnostics are not claimed to be resolved. A baseline protocol investigation is needed before modifying the bundled worker communication library.
- In-memory merges/bulk replacements are not atomic. On failure, previously appended sprites or completed replacements can remain; earlier changes are not rolled back. Strict failures prevent the affected object from being installed with unmapped IDs or preview placeholders. Review partial work before saving.
- Existing reusable bitmap caches and managed allocations are not evidence of an unbounded leak. Long-duration process-memory and handle-count profiling remains necessary; the single UI memory observation is not a stability proof.
- Some asynchronous worker jobs use timer-driven batches. This audit does not establish cancellation safety for every import/export task or every rapid-close race. The explicitly corrected selection/file-input/merge callbacks have regression coverage.
- Save/compile command ordering is tested by intercepting commands. This does not certify every worker acknowledgement race or undo/edit sequence.
- The real-data integrity check covers the tested unchanged-format export, not every custom client version, every alpha conversion, every server attribute or all destructive editing workflows. DAT reopen/count checks are not an exhaustive equality proof for every metadata property.
- Staged publication handles ordinary I/O failure, not crash-atomic publication during power loss. Retain an independent backup.
- Native AIR/SWC internals and third-party code are outside source-level ownership verification. A raw native UAF cannot be ruled out by managed-code inspection.

CodeRabbit CLI was not installed in this environment, so the optional `coderabbit review --agent` command was not run. The supplied findings were checked directly and validated locally; no automated review is claimed.
